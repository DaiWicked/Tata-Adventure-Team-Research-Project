# 09 · 真机动态验证记录（SM-G973F / Android 10）


## 0 结论先摆

1. **UI 完全可达，游戏能正常进主城**，没有任何 GM/调试面板暴露在界面里（截图 `captures/device/screen_01.png`、`screen_02.png`）。
2. **任何 ptrace 式插桩都会被杀**：5 次实测（3 次 attach + 2 次 spawn），进程 1~4 秒内 `has died: fore TOP`，无 tombstone、无 ANR。
3. 但 **frida-server 常驻本身不触发**（不 attach 时连跑 45 秒无异常）。触发点是 **ptrace 附着**，不是"多了一个进程"。
4. 因此"内存 dump 解密后的 Lua / 元数据"这条路，**必须换注入方式**（Zygisk gadget 或 `wrap.<pkg>` + `LD_PRELOAD`），继续用 attach 是白费。

## 3 决定性实验：什么行为才会被杀

| 实验 | 条件 | 结果 |
| --- | --- | --- |
| A | **不跑** frida-server，正常启动 | 存活（跑满 40s 检查仍在） |
| B | frida-server 常驻，**不 attach** | **存活**（45s 后仍在） |
| C | attach 到已运行进程，加载 `03_scan_lua.js` | 脚本 load 成功，1~4 秒后进程消失 |
| D | attach 到已运行进程，加载 `07_quick_dump.js`（load 阶段同步扫描） | attach 阶段即 `TransportError: agent connection closed unexpectedly`，进程已死 |
| E | `spawn` 模式 + `08_early_stealth.js`（路径屏蔽 + libcheck 中和） | 脚本跑了，resume 后仍被杀 |
| F | `spawn` 模式 + `09_hide_tracer.js`（TracerPid 抹 0） | **TracerPid 读取被成功替换 4 次**，进程仍被杀 |

结论：检测不是"扫描 /proc 发现可疑进程"，而是**发现自己被 ptrace**；并且**不止一层**（第 6 行证明壳确实读 `/proc/self/status`，抹了它照样死）。

## 6 加密复核：ECB-8、全局密钥、无 IV（34 个真机文件独立复验）

- 34 个 `.luae` 与 APK 内一致：`FF FF FF FF` + u32 明文长度 + 密文。
- **31/34 个文件在 offset `8..16` 的第一块密文完全相同 = `97eed49415102796`** —— 这块正是 `pgame.pkg` 里出现 6,516 次的最高频块，也是 `LanguageDbZH.luae` 的首块。→ 密钥全局共用、无 IV、确定性映射。
- 跨 31 个文件共 **703 种重复 8 字节块**；同一块出现在不同偏移（`0ddc8e6e38bb013c` 在 0x720 / 0x968 / 0x23f0 / 0x10848）→ **位置无关，就是 ECB-8**。
- 单文件内重复几乎为 0（`PinballTrickBuffTest` 4,825 块 0 组；`PinballTrickCardFlow` 8,458 块仅 10 组/21 块）。
- `bytes[8..12)` 在文件间成组重复（`2a65dd46`×4、`5966693f`×5、`ad228550`×4、`fb5d95d1`×4…），`bytes[12..16)` 每文件唯一 → 疑为"组 id + 每文件 seed"。

**判定不变**：算法自定义（非 AES/DES/SM4/XXTEA），密钥运行时装配；能改密文（块替换/剪贴）但读不出明文。见 `03-资源容器与块加密.md`。

## 8 下一步（按性价比排序）

1. **`wrap.<pkg>` + `LD_PRELOAD` 内嵌 gadget**（本机 `ro.debuggable=1`，`setprop` 可用，无需 reboot）
   - 优点：不进 ptrace，壳看不到 TracerPid 变化；注入发生在进程内
   - 代价：需要 `frida-gadget-*-android-arm64.so`（GitHub release 下），且 gadget 的 socket/maps 仍可能被扫到
2. **Zygisk 模块注入 gadget**：更彻底（无独立进程、无 socket），但要装模块 + 重启，SELinux/magisk 环境要重配
3. **纯抓包**：不碰进程，只做网络侧取证（服务端权威性、签名参数、金币/通行证下发）。需要一台能跑 mitmproxy 的 64 位环境
4. 放弃 dump，转**纯静态 + 已有 Test 清单**做推理（`04`、`08` 两篇已覆盖）

> 按"事不过三"：ptrace 插桩这条线已经试了 5 次，到此为止，不再在 attach 上耗时间。
