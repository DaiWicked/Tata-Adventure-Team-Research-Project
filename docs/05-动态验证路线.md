# 05 动态验证路线（真机 + Frida + mitmproxy）

静态能证明的到此为止。剩下三件事只能动态拿：

1. `.luae` / `pgame.pkg` 解密后的**明文**（Lua 逻辑 + 数值表）；
2. `global-metadata.dat` 解密后的**明文**（业务类名、字段名）；
3. 通行证 / 金币 / GM 命令在**服务端**到底校不校验。

## 0. 前置环境

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 设备 | 真机（arm64），Android 10+ | 模拟器会被 `libcheck` 抓（`Emulator`、qemu 库、buildroid 目录） |
| Root | Magisk + Zygisk | 需要 `DenyList` 里勾选游戏包名，隐藏 root |
| Frida | `frida-server 17.26.3 arm64`，改名跑（如 `fsrv`） | 默认端口 27042 会被扫 |
| 网络 | mitmproxy ≥10 + 系统证书 | 需要把 CA 装到系统证书区（Magisk 模块） |
| 备份 | 首次进入前做全量快照 | 出问题可回滚 |

> 注意：本机（Windows）上跑的是 `adb` + `frida`，脚本里只出现 `DEVICE`、`PACKAGE`、`OUT_DIR`
> 这类占位符；实际设备信息属于你自己的环境。

## 1. 先过反调试（否则后面全白做）

`libcheck.so` 的导出符号名字很直白，直接 hook 掉：

```javascript
// scripts/frida/01_neutralize_check.js
Java.perform(function () {
  var check = Module.findBaseAddress('libcheck.so');
  if (!check) { console.log('[!] libcheck.so 未加载'); return; }
  ['antiFile', 'antiProperty', 'antiPropertyValueContains'].forEach(function (name) {
    var p = Module.findExportByName('libcheck.so', name);
    if (!p) { console.log('[!] 无导出 ' + name); return; }
    Interceptor.attach(p, {
      onEnter: function (args) { console.log('[check] ' + name + ' -> ' + args[0]); },
      onLeave: function (ret) { ret.replace(ptr(0)); }   // 一律"没检测到"
    });
  });
});
```

另外 `libigame.so` 导入了 `pclose` / `snprintf`，说明它会 `popen()` 跑 shell 命令做检测。
把 `popen` 的入参打出来，就知道它查了什么（通常会看到 `su`、`frida`、`/proc/self/maps`）：

```javascript
['popen', 'system'].forEach(function (n) {
  var p = Module.findExportByName(null, n);
  if (p) Interceptor.attach(p, { onEnter: function (a) { console.log('[' + n + '] ' + a[0].readCString()); } });
});
```

`libnesec` 那层还会读 `Settings.Secure.adb_enabled`（见 02 篇字符串还原），
真机测试时把开发者选项关掉、USB 调试仅在使用时开。

## 2. dump IL2CPP 元数据明文

元数据解密后必然以 `AF 1B B1 FA`（`0xFAB11BAF`）开头躺在内存里。不需要知道解密函数在哪：

```javascript
// scripts/frida/02_dump_metadata.js
var MAGIC = 'af 1b b1 fa';
function scanOnce() {
  var ranges = Process.enumerateRanges('r--').concat(Process.enumerateRanges('rw-'));
  for (var i = 0; i < ranges.length; i++) {
    var hits = Memory.scanSync(ranges[i].base, ranges[i].size, MAGIC);
    if (hits.length) {
      console.log('[+] metadata @ ' + hits[0].address + ' in ' + ranges[i].base + ' (' + ranges[i].size + ')');
      // 头部第 8 字节起是 version，第 12 字节起是各 section 偏移；先整段 dump 再按版本切
      var size = 10 * 1024 * 1024; // 已知文件 10,033,692 B，取上限
      var buf = hits[0].address.readByteArray(size);
      var f = new File('/data/local/tmp/global-metadata.dec', 'wb');
      f.write(buf); f.flush(); f.close();
      return true;
    }
  }
  return false;
}
setTimeout(function () { if (!scanOnce()) console.log('[!] 未命中，改为按页轮询'); }, 8000);
```

拿到明文后就能用 Il2CppDumper / Il2CppInspector 离线还原全部类、字段、方法签名——
那时候"通行证""金币"对应的 C# 类与字段会直接暴露，比 Lua 层更早一步。

## 3. dump 解密后的 Lua

两条互补路子：

**3.1 扫 Lua 字节码 magic**（`1b 4c 75 61` = `\x1bLua`，Lua 5.1/5.3/5.4 通用）

```javascript
// 扫到就 dump 一块，命名用地址
var hits = Memory.scanSync(range.base, range.size, '1b 4c 75 61');
hits.forEach(function (h, i) {
  var p = h.address.sub(12);                 // 前面可能有 12 字节 chunk 头字段
  var buf = p.readByteArray(256 * 1024);
  var f = new File('/data/local/tmp/lua_' + h.address + '.luac', 'wb');
  f.write(buf); f.flush(); f.close();
});
```

**3.2 找 `luaL_loadbufferx` 的调用点**

`libil2cpp.so` 的 `.dynsym` 被加密，`enumerateSymbols` 拿不到 Lua 符号。可行替代：
在 `libil2cpp.so` 里做特征码搜索（找 `luaS_newlstr` / `luaD_precall` 的常量串引用），
或者更省事——**直接 hook `tolua_*` 不现实时，优先用 3.1 的扫描**。

> 实测提醒：`pgame.pkg` 的 Lua 是打包进一个 19 MB 加密容器里的，运行时是**逐条解密加载**，
> 所以扫描要等场景加载完（进主界面再扫，别在闪屏扫）。

## 4. 看住请求签名（这一步决定"改包"可行不可行）

`libparkcrypto.so` 的导出是干净的，`frida` 直接 `findExportByName` 就能挂：

```javascript
// scripts/frida/04_watch_signature.js
var addr = Module.findExportByName('libparkcrypto.so', 'parkcrypto_generate_signature');
if (addr) {
  Interceptor.attach(addr, {
    onEnter: function (args) {
      // 参数含义未知，先把 0..4 号参数当字符串/指针打出来，再对照 build_signature_base_string
      console.log('[sign] a0=' + args[0] + ' a1=' + args[1] + ' a2=' + args[2] + ' a3=' + args[3]);
      try { console.log('  base  = ' + args[1].readCString()); } catch (e) {}
    },
    onLeave: function (ret) { try { console.log('[sign] -> ' + ret.readCString()); } catch (e) {} }
  });
}
// 想直接拿 base string，挂这个更直观
var base = Module.findExportByName('libparkcrypto.so', 'parkcrypto_build_signature_base_string');
if (base) Interceptor.attach(base, { onEnter: function (a) { console.log('[base] ' + a[0] + ' ' + a[1]); } });
```

拿到 `base string` + 签名结果，就能反推签名算法（排序→拼接→加 secret→摘要）。
**这一步只做"看懂"，不做"伪造"**：本项目不提供绕过服务端校验的脚本。

## 5. 抓包

```bash
# 设备端（Magisk 模块把 CA 装进系统证书后）
adb shell settings put global http_proxy 127.0.0.1:8080   # 或用 mitmproxy 的透明代理模式
mitmproxy -p 8080 --set confdir=./.mitm
```

判读要点：

- 请求体是否是明文 JSON / protobuf？（UnityWebRequest + 签名通常是明文 body + header 带 sign）
- `os_type`、`version`、`sign`、`timestamp` 这几个字段必然出现（对应 `parkcrypto` 的日志）。
- 通行证/金币相关接口的**返回**字段：服务端是给"增量"还是"全量"？给全量的接口重放价值更高
  （这也是测试重点：重放一次看服务端是否幂等）。

## 6. 验证清单（按优先级）

| # | 假设 | 怎么验 | 判定 |
| --- | --- | --- | --- |
| 1 | 金币是服务端账本 | 断网重进，看余额；改内存后触发一次消耗 | 余额回滚 / 消耗被拒 → 服务端权威 |
| 2 | 通行证等级服务端下发 | 抓包看登录返回里是否有 pass 字段；改内存后再看 | 被覆盖 → 服务端权威 |
| 3 | 战斗结算有服务端校验 | 改战斗数值打一局，看结算上报是否被拒 | 上报被拒 → 有校验 |
| 4 | **GM 命令鉴权在服务端** | 找 GM 入口（`eGmSess`/`ServerContro`/`Qdebug`），本地打开开关发一条无害命令（如 `gm help`） | 返回"无权限"→ 安全；返回数据 → **高危** |
| 5 | 资源完整性校验在哪 | 改一个 `.luae` 的 1 个块，重签装包，看是否被 `InpackageFileHash` 拦 | 启动即崩/提示校验失败 → 校验在客户端且未 patch |
| 6 | 是否有证书 pinning | mitmproxy 抓包看是否 TLS 失败 | 失败 → 有 pinning，需 hook `SSL_verify` 或 OkHttp |

第 4 条是整个项目里**唯一**值得投入的高价值方向：GM 模块的存在（`GMail`、`GMSearch`、
`eGmSess`、`ServerContro`、`Qdebug`、`DTest`）说明代码在包里；能不能用，取决于服务端。
行业里绝大多数情况是「服务端校验角色白名单」——所以先假设安全，用测试去证伪。

## 7. 纪律

- 只在**自有设备 + 测试账号**上做，不动线上数据、不带入真实支付。
- 每次改动前 `adb shell` 里备份 `/data/data/<pkg>`；改包失败就装回原包。
- 抓包内容里会有 token，落盘前脱敏，别把抓包文件提交进仓库（`.gitignore` 已排除 `*.log`，
  建议再自行忽略 `captures/`）。
