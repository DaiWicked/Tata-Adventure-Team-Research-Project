# 10 真机内存取证：拿到解密后的元数据与 Lua

> 目标：静态侧卡在两处加密上 —— `global-metadata.dat`（易盾 HTPX 容器）和 `pgame.pkg` / `*.luae`（自研 8 字节分组）。本篇记录**怎么在真机上把这两样东西的明文拿到**，以及拿到了什么。
> 方式：**只读取证**。不改内存、不改包、不伪造请求；产物只落在本工作区与设备 App 私有目录。

## 1. 先失败的那条路：frida 注入

| 方式 | 结果 | 证据 |
| --- | --- | --- |
| `frida-server` + attach | 1~4 秒内进程被杀 | `Process ... has died: fore TOP`，无 tombstone |
| `frida-server` + `spawn` + 抹 `TracerPid` | 命中 4 次仍被杀 | logcat 5 条 `avc: denied` |
| `wrap.<pkg>` + `LD_PRELOAD` 内嵌 gadget（listen 模式） | 多进程抢 27042 端口自崩 | `Failed to start: Error binding to address 127.0.0.1:27042: Address already in use` |
| gadget（script 模式）+ 封 `exit`/`_exit`/`abort`/`syscall(231)` | 进程能活 20 秒以上，但**加载流程被卡死** | `hook.log` 里 `blocked exit` 出现，但 `il2cpp=false`、截图全白 |
| gadget 加载后不干预 | 每 ~2.5 秒一对进程起落，`libil2cpp` 段数恒为 0 | `scan.log`：`round 1 il2cpp=false` 反复 |

结论：易盾在 Unity 起来之前就会看到 `/data/local/tmp/libgadget.so` 这个外来模块并杀进程。
**注入这条路要过就得先做模块隐藏（Zygisk/改名+改路径+改 maps），成本高且要动系统。**

## 2. 走通的那条路：root 直读 `/proc/<pid>/mem`（不注入）

不注入 = 不触发那条检测链。做法：

1. 清掉 `wrap` 属性，让 App 正常启动（实测 `libil2cpp` 有 8 个段，游戏正常进主城）。
2. 用 magisk root 从进程外按 mapped range 逐块 `dd` 读 `/proc/<pid>/mem`。
3. 拉回本地，用 Python 扫魔数与明文特征。

```bash
adb shell "su -c 'setprop wrap.com.lilithgame.pgame.android.cn \"\"'"
adb shell "su -c 'am force-stop com.lilithgame.pgame.android.cn; am start -n com.lilithgame.pgame.android.cn/com.farlightgames.igame.SplashActivity'"
py -3 scripts/pull_ranges.py <pid> --auto --min 8 --max 200
```

坑（都踩过了）：

- `adb shell` 会改写 `/data/local/tmp/...` 成 Windows 路径 → 必须 `MSYS_NO_PATHCONV=1`（见 `scripts/adb.sh`）。
- 设备侧 `dd | grep -aob` 的偏移不可信；mksh 对 >4GB 的 16 进制地址做算术会溢出 → 偏移一律在 Python 里算成十进制再交给 `dd`。
- `adb exec-out` 才是二进制安全的；`adb shell` 会做 CRLF 处理。
- `/data/local/tmp` 是 `0771 shell:shell`，App uid 建不了文件（这条坑了 gadget 版 hook 一整轮）。

## 3. 拿到了什么（证据）

### 3.1 IL2CPP 元数据：HTPX 容器在堆上

dump `captures/device/memdump/pid23728_0x7d62924000_9MB.bin`（`[anon:libc_malloc]`，9.6MB）开头：

```
0000  48 54 50 58 1c 1a 99 00  00 01 00 00 88 c2 02 00   HTPX  ........
0010  88 c3 02 00 20 61 0a 00  a8 24 0d 00 d8 b0 15 00
```

- `00..03` = `HTPX`（易盾容器 magic，和 APK 里 `global-metadata.dat` 的头一致）
- `04..07` = `0x00991A1C` = **10,033,692** = APK 里 `global-metadata.dat` 的**确切字节数**
- `08..` = 明文元数据本体

结构验证（`scripts/10_carve_metadata.py` 的输出即证据）：

| payload 偏移 | 内容 | 判据 |
| --- | --- | --- |
| `0xD24A8` | 字符串表 | 开头是 `Assembly-CSharp.dll\0<Module>\0EmbeddedAtt…` |
| `0x2C288` | stringLiteral 表 | 每项 `u32 长度 + u32 索引`，实测首项 `len=4` |
| `0xA6120` | stringLiteral 数据 | `…attempt to index a nil value` 等 Lua 报错串 |
| `0x18C72D` | — | `UnityEngine.CoreModule` |

**关键点：payload 头部没有 `af 1b b1 fa`（sanity）也没有 version** —— 易盾把这两项换掉了，
所以现成工具会判定"这不是 metadata"。但这不影响取证：字符串表和 stringLiteral 表都在原位，
直接从 header[4] 读字符串表偏移即可。

抽取结果：**81,266 条符号（去重）** → `notes/10-metadata-strings.txt`。抽样：

- 调试：`isDebugMode`、`SetDebugLogActive`、`igame_getDebugSwitch`、`OpenZbsDebugger`、`gm_show`
- 性能/上报：`perfReport`、`PerfRecordData`、`LuaMemReport`、`Push_System_Action_PerfReport_*`

注意：元数据里几乎都是**引擎与三方 SDK 的符号**，游戏业务逻辑在 Lua 侧 —— 这与
`docs/07` 的"索引里全是 Lua 模块名"互相印证。

### 3.2 Lua：明文就在 144MB 的 malloc 段里

dump `captures/device/memdump/pid23728_0x7d9091a000_144MB.bin` 命中：

- **51 处 Lua 5.4 预编译块头**：`1b 4c 75 61 54 00 19 93 0d 0a 1a 0a`（`0x54`='T' → Lua 5.4）
- **6,282 条 `.luae` 模块路径** → `notes/11-lua-modules.txt`
- 函数级 chunk 名：`Src_UI_Pinball_Scene_PinballScene`、`Src_UI_PinballBuff_PinballTrickCalc` …

`scripts/11_carve_lua.py` 把 51 个块切到 `unpack/lua/*.luac`（块边界按堆布局切，不是文件边界，
所以单块内部是"文件碎片 + 相邻内存"，但块头与内联字符串都是真的）。

## 4. 这些发现改变了什么判断

| 之前的判断（`docs/04`/`docs/08`） | 现在（有证据后） |
| --- | --- |
| 业务逻辑完全不可读，只能从索引名猜 | **Lua 模块清单 6,282 条 + 元数据符号 81,266 条可读**，功能边界能画出来了 |
| `Tabs/GM` 只是被切尾的索引串，不确定有没有实现 | **有实现**：`GMBaseTab` + 6 个 Tab + `GMCommands`/`GMCommandGroup` + `LuaCodeRunner` |
| 通行证只是 `xDPass`/`PassAsse` 之类的碎片 | **完整模块族**：Config 4 张表 + Entrance/View 7 个界面 + Mall 入口 |
| 资源加密是主要障碍 | **加密只保护"静态文件"，运行期全在堆里明文** → 它挡的是改包，不是取证 |

但**"能不能改金币"这个结论没有变**：能看到 UI 有 GM 面板，不等于能用它 ——
GM 命令是否生效取决于服务端是否给这个账号开了权限（`docs/08` §2 的判定链没有变）。
新增的可验证点只有一条：**`Config/GMCommands.luae` 的命令表能不能在客户端被枚举出来**
（下一步：从 `unpack/lua/` 里把这张表挖出来，看每条命令有没有 `need_gm`/`need_server` 之类的前置位）。

## 5. 复现清单

```bash
# 1) 设备侧准备（一次性）
bash scripts/adb.sh shell "su -c 'setprop wrap.com.lilithgame.pgame.android.cn \"\"'"

# 2) 正常启动游戏，等进主城
bash scripts/adb.sh shell "su -c 'am force-stop com.lilithgame.pgame.android.cn; am start -n com.lilithgame.pgame.android.cn/com.farlightgames.igame.SplashActivity'"

# 3) 拿 pid，拉候选内存段（8~200MB 的非系统段，约 400MB）
P=$(bash scripts/adb.sh shell "ps -A | grep 'com.lilithgame.pgame.android.cn$' | awk '{print \$2}'" | tr -d '\r')
py -3 scripts/pull_ranges.py $P --auto --min 8 --max 200

# 4) 切元数据 + 抽符号
py -3 scripts/10_carve_metadata.py captures/device/memdump/pid*_0x7d62924000_9MB.bin

# 5) 抽 Lua 模块表 + 字节码块
py -3 scripts/11_carve_lua.py captures/device/memdump/pid*_0x7d9091a000_144MB.bin
```

## 6. 边界

- 只用 root 读内存，**不写内存**、不改进程、不 hook 运行中的游戏。
- 不构造/不重放任何请求；**没有碰服务端**。
- dump 与切出来的明文都在本工作区（`captures/`、`unpack/metadata/`、`unpack/lua/`，均被 `.gitignore` 排除）。
- 设备侧的临时文件（`/data/local/tmp/*.sh`、`libgadget*`、`q_*`）用完应清理；`hook.log`/`scan.log` 在 App 私有目录，随 `pm clear` 消失。
