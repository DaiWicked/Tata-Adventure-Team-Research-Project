# 04 破解面评估：通行证、金币到底能不能本地伪造

## 0. 先给结论

| 作用域 | 本地可改 | 改完是否"真" | 卡在哪 | 性价比 |
| --- | --- | --- | --- | --- |
| **通行证等级 / 领取状态** | 可以（改 Lua 变量或内存） | **假**：只在本次运行有效，重连即被服务端覆盖 | 服务端下发 + 领取接口二次校验 | 低（只有自我满足） |
| **金币 / 钻石余额** | 可以（改内存/改本地缓存） | **假**：不进账本，任何消耗校验都会失败 | 服务端账本 + 签名 | 低 |
| **礼包 / 商品价格** | 可以（改本地 Lua 表） | **假**：下单金额由服务端算 | 服务端下单接口 | 低 |
| **战斗数值（本地战斗）** | 可以（改 Lua / 改内存） | **半真**：单机过程有效，结算上报可能被校验/回放 | 战报校验（需实测） | 中 |
| **皮肤 / 文本 / 图标 / UI** | 可以（ECB 块替换，见 03 篇） | **真**（只影响自己看到的） | 完整性 hash 清单 + 重签 | 中 |
| **跳过动画 / 加速 / 去广告 / 改界面** | 可以（Lua patch / Frida） | **真**（体验收益） | 易盾壳 + 反调试 | 高 |
| **GM 命令（若客户端可触发）** | 待验证 | **可能真**（最高危假设） | 服务端是否校验角色权限 | **最高** |

一句话：**这个包支持"本地伪造数据"，但不支持"伪造出线上资产"。** 金币和通行证属于后者。

## 1. 判定依据（为什么能下这个结论）

### 1.1 客户端里没有"钱包"

- 全包搜索持久化 API：`libil2cpp.so` 里与存档相关的只有
  `UnityEngine.Application::get_persistentDataPath()` 1 处、`PlayerPrefs` 系列 7 个符号
  （`Save/TrySetSetString/GetInt/GetString/GetFloat`）。
- `libkeva.so`（火山引擎 Keva）是埋点 KV，不是游戏存档；没有 `shared_prefs`、`.sav`、
  MMKV 明文路径串。
- 结论：**客户端不存"我有多少金币"这种权威数据**，最多缓存登录 token、设置项、上次选关。
  没有本地钱包，就没有"改本地文件得到金币"这条路。

### 1.2 服务端在线且带签名

- `assets/ParkConfig.json`：`park_server_region:"lilith"`、`parkway_env_ids:["prod..."]`
  → 正式环境在线。
- `libparkcrypto.so`：`parkcrypto_generate_signature` / `parkcrypto_build_signature_base_string`，
  日志里 `get_decrypted_secret: ... using default win prod key`、`missing required parameter: os_type`
  → **每个请求带签名，secret 运行时解密**。改包/重放不加签名等于自曝。

### 1.3 Lua 里确实有经济系统的"全套界面与请求层"

`assets/pgame.pkg.bin` 是**未加密的索引**，从中还原出的模块名（`scripts/06`，启发式提取，
名字尾部偶有粘连的长度字节）直接暴露了系统构成：

| 模块名（还原） | 推断用途 |
| --- | --- |
| `xDPass`、`PassAsse`、`PassWeeklyTas` | **通行证**（Pass / 通行证任务与奖励领取） |
| `AGold`、`ShowCoin`、`SilverCoinD`、`eGolden`、`RankGoldRu` | **金币/银币** 的显示与结算 |
| `uCashierL`、`uirstPay`、`ThirdPartyPaymentClub`、`WebPayClub`、`aCharge` | 收银台、首充、三方支付、网页支付 |
| `MonthlyC`、`WeekCard`、`mCard`、`ACard`、`yCardGif` | 月卡 / 周卡 / 卡券 |
| `SeasonSkill`、`bSeason` | 赛季（技能/奖励） |
| `CShop`、`FShop`、`qileShop`、`P9EShop`、`EShopM`、`ShopListBuild` | 商店与商品列表构建 |
| `H2Box`、`QBoxFXO`、`GiftNotifyB`、`OpenServerGift` | 宝箱、礼包、开服活动 |
| `AGold`/`AItem`/`ACard`/`ATeamL`/`ARank` | 一类 `A*` 前缀的数据访问层（金币/道具/卡/队伍/排行） |

**这印证了"客户端有完整的商城/通行证/首充逻辑"，但也说明它们只是"发起请求 + 渲染结果"
的那一层**：`ShopListBuild`（构建商品列表）、`ShowCoin`（显示金币）这类命名本身就是
"展示层"语义。

### 1.4 客户端内含 GM / 调试模块

索引里还能捞到：`GMail`、`GMSearch`、`GVG...`、`eGmSess`、`Qdebug`、`DTest`、`TTestT`、
`ServerContro`（ServerControl）、`LocalBug`、`RuntimeCostTime`、`ProtoTest...`。

正式包里带 GM/测试代码很常见，通常是**UI 入口被开关隐藏、命令仍可达**。这是本项目里
唯一有"真收益"可能的点：

```
如果 GM 命令的鉴权只在客户端（一个 bool / 一个开关）
  → 本地把开关打开，就能发 GM 命令
  → 服务端若只校验"是不是合法命令"而不校验"这个角色是不是 GM"
  → 这才会真的产生金币
```

> 这条**必须动态验证**（见 05 篇验证清单 #4）。静态只能证明"代码在包里"，证明不了
> "服务端不校验"。行业惯例是服务端会校验角色白名单，所以先把它当"待证伪的最高危假设"，
> 而不是结论。

## 2. 四条落地路线（按成本从低到高）

### 路线 A：Frida 改内存（不改包，不碰签名）

- 目标：金币显示、通行证等级显示、战斗数值、跳过动画。
- 做法：attach 后扫内存 / hook Lua 的取值函数；配置改动只在本次进程有效。
- 成本：**低**（1 天量级，前提是过了反调试）。
- 收益：体验类为真；资产类为假（重登回滚）。
- 风险：易盾会检测 Frida（见 02 篇 `libcheck`），需要 Magisk DenyList + 改名 frida-server。

### 路线 B：dump 解密后的 Lua / 元数据（研究向）

- 目标：看懂逻辑，找"服务端漏校验的接口"。
- 做法：内存扫 `1b 4c 75 61`（Lua 5.x 字节码 magic）与 `AF 1B B1 FA`（IL2CPP 元数据 magic），
  命中即 dump（05 篇给了脚本骨架）。
- 成本：**中**（要写扫描 + 落盘 + 校验完整性）。
- 收益：一切后续工作的前提；**这是唯一能回答"哪个接口缺校验"的路径**。

### 路线 C：改包（资源/文本/UI）

- 目标：换皮肤、改文案、去广告位、加速。
- 做法：ECB 块替换（03 篇）→ 重新计算 `InpackageFileHash` 里的哈希（或 patch 校验）→ 重签 APK。
- 成本：**高**（三座山：块拼接要对齐、哈希要重算、签名要过易盾）。
- 收益：只影响本地观感。

### 路线 D：改包 + 签名 hook（改协议）

- 目标：篡改请求参数（例如领奖次数、任务进度）。
- 做法：hook `parkcrypto_generate_signature`，让签名函数对**你改过的参数**签名；
  再让 mitmproxy 转发。
- 成本：**高**，且**这一步就是"攻击线上服务"的红线**——本项目不做、不提供脚本。
- 说明：即使技术上做得通，服务端对进度类字段通常有服务端侧状态机，改参数只会得到
  "非法请求"或风控标记。

## 3. 明确"不支持"的部分

- ✗ 本地伪造出可用的金币/钻石/通行证等级（无本地账本，服务端权威）。
- ✗ 通过改 `nedata.db` 或 `pgame.pkg` 让服务端认账（这些是**客户端配置**，服务端有自己的表）。
- ✗ 离线游玩绕过（`park_server_region` 指向线上环境，登录与存档都在服务端）。
- ✗ 用旧版本 APK 降级刷资源（`parkcrypto` 参与 `os_type`/版本，服务端会校验版本）。

## 4. 如果目标只是"自己玩得爽"，推荐顺序

1. **Frida 内存改数值**（金币显示、战斗属性、跳过动画）——成本最低，收益最直接。
2. **dump Lua 看配置**——知道自己改的字段是什么意思，避免改崩。
3. 改包换皮/改文案——纯观感，成本最高，最后做。

如果目标是"研究它为什么防得住"，那就按 05 篇走一遍：元数据 → Lua → 签名 → 抓包，
把每一层的 hook 点跑通，这套方法论可以复用到任何"Unity + 易盾 + 自研资源加密"的包上。
